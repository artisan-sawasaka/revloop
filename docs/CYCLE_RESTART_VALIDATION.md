# 回数上限後のカウントリセット

2026-10-19実装。所有者の「回数上限で停止した後にrevloopを再実行したら、レビューカウント0から実行する」という指定に対応。

## 動作

- MAX_ROUNDSのrunへ公開CLIの `review --run <UUID>` を再度実行すると、新サイクルを開始する。`restart --run <UUID>` も同じ開始操作。
- この呼び出し自体は認証確認と状態移行だけを行い、モデル推論を行わない。今回のカウントは0、上限は現在の共通設定。次の修正・レビューは元チャットで通常どおり継続する。
- `reviewCount` と `totalReviewCount` を区別。履歴のround番号は累計であり、削除や巻き戻しを行わない。
- 未解消指摘、セッション、文脈、ファイル範囲、過去入力と指摘の停滞履歴を保持。停滞回数とタイムアウトも既存値を維持。
- MAX_ROUNDSだけが対象。STOP、停滞、エラー、未完了のレビュー等は解除しない。認証確認失敗とアカウント変更時もリセットしない。拒否理由は試行ディレクトリとhistoryに記録する。
- 同じ自動ループ内では上限で停止。ユーザーによる次のrevloop呼び出しが新サイクル開始の合図であり、追加の例外許可は求めない。両ホストの共通Skillへ反映した。
- Claudeは現在のauth-only方式を維持。`/usage` は呼ばず、残量・追加利用OFFを検証したとは扱わない。Codexの課金ガードは維持。
